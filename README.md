# LifeMart Safety

Telegram-бот для модерации спама в чате. Сообщение проходит через три фильтра (keyword, TF-IDF, эмбеддинги), результаты сводит мета-классификатор, решение принимает политика по режиму и порогам.

**Метрики исследовательской схемы (n=1126):** ROC-AUC 0.998, Precision 0.99, Recall 0.99, Brier 0.006.

**Операционные характеристики:**
- Латентность: 850 ms среднее, 1200 ms p95
- RAM: 500–800 MB
- Артефакты: 5 файлов, 120 MB (в репозиторий не входят, см. `.gitignore`)
- Зависимость: Ollama с моделью `qllama/multilingual-e5-small`, GPU желателен

---

## Как работает

1. Keyword и TF-IDF фильтры дают быстрые оценки по тексту.
2. Embedding Filter считает косинусное сходство сообщения с 11 прототипами семейств (7 спам, 4 норма), с контекстом чата и историей пользователя. Провайдер эмбеддингов: Ollama, Mistral API, local или disabled.
3. Мета-классификатор (LogisticRegression, 41 признак, калибровка) объединяет выходы фильтров, контекст и whitelist-попадания, выдаёт итоговую `p_spam`.
4. PolicyEngine сравнивает `p_spam` с порогами с учётом понижающих множителей и режима.

**Режимы:**
| Режим | Действия |
|---|---|
| `manual` | только уведомление модератора |
| `semi-auto` | уведомление + удаление |
| `auto` | уведомление + удаление + бан |
| `legacy-manual` | старый поток: Keyword → TF-IDF, мета-классификатор не используется |

**Понижающие множители** (умножаются на `p_spam` до сравнения с порогами): ответ сотруднику 0.90, анонс из канала 0.85, whitelist-лексика 0.85, упоминание бренда 0.70. Множители складываются мультипликативно.

При недоступности эмбеддингов бот работает по legacy-потоку, precision падает на 15–20 п.п.

## Быстрый старт

```bash
git clone https://github.com/your-org/LifeMart_Safety.git
cd LifeMart_Safety

python -m venv .venv
. .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env        # заполнить значениями
python main.py
```

Python 3.10 или новее. Бот запускается в polling-режиме; `main.py` проверяет `BOT_TOKEN` и `MODERATOR_CHAT_ID` и выходит с кодом 2, если они не заданы. Для продакшена оберните в сервис (systemd, pm2, supervisord) с автозапуском и политикой рестартов.

## Конфигурация (.env)

**Обязательные:**
| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `MODERATOR_CHAT_ID` | ID чата модераторов (канал или группа) |
| `WHITELIST_USER_IDS` | ID через запятую: доступ к административным командам |

**Политика:**
| Переменная | Назначение | По умолчанию |
|---|---|---|
| `POLICY_MODE` | режим модерации | `semi-auto` |
| `META_NOTIFY` / `META_DELETE` / `META_KICK` | пороги уведомления, удаления, бана | 0.65 / 0.85 / 0.95 |
| `LEGACY_KEYWORD_THRESHOLD` / `LEGACY_TFIDF_THRESHOLD` | пороги legacy-потока | 0.60 / 0.65 |
| `META_DOWNWEIGHT_*` | понижающие множители | 0.70–0.90 |
| `ANNOUNCE_BLOCKS` | публиковать ли уведомления о бане в чате | `True` |

**Эмбеддинги:**
| Переменная | Назначение | По умолчанию |
|---|---|---|
| `EMBEDDING_MODE` | провайдер: `api` / `ollama` / `local` / `disabled` | `ollama` |
| `MISTRAL_API_KEY` | ключ Mistral, нужен при `EMBEDDING_MODE=api` | — |
| `EMBEDDING_MODEL_ID` / `OLLAMA_MODEL` / `OLLAMA_BASE_URL` | модель и адрес провайдера | e5-small / localhost:11434 |
| `EMBEDDING_TIMEOUT_MS` | таймаут запроса эмбеддингов | 800 |
| `EMBEDDING_ENABLE_USER` | считать пользовательскую капсулу (дороже) | `False` |
| `CONTEXT_HISTORY_N` / `CONTEXT_MAX_TOKENS` | размер и лимит контекстной капсулы | 4 / 512 |
| `EMBEDDING_CACHE_TTL_MIN` | TTL кэша user-эмбеддингов | 10 |

**Артефакты и прочее:**
| Переменная | Назначение | По умолчанию |
|---|---|---|
| `CENTROIDS_PATH` / `PROTOTYPES_PATH` / `META_MODEL_PATH` / `META_CALIBRATOR_PATH` | пути к артефактам ML | `models/*` |
| `RETRAIN_THRESHOLD` | число новых примеров для рекомендации `/retrain` | 100 |
| `LOG_LEVEL` / `DETAILED_DEBUG_INFO` | глубина логирования, детализация карточек | INFO / True |

Полный список полей и дефолты: `config/config.py`.

## Команды

Доступ к административным командам имеют ID из `WHITELIST_USER_IDS`.

| Команда | Назначение |
|---|---|
| `/start`, `/help` | справка для пользователя и модератора |
| `/status` | состояние фильтров и очереди модерации |
| `/debug <id>` | карточка анализа конкретного события |
| `/meta_info` | статус и параметры мета-классификатора |
| `/setpolicy <mode>` | сменить режим на лету |
| `/setthreshold <notify\|delete\|kick> <value>` | сменить порог на лету |
| `/setdownweight <flag> <value>` | настроить понижающий множитель |
| `/resetconfig` | сбросить runtime-настройки к `.env` |
| `/retrain` | переобучить TF-IDF на локальной выборке |

Runtime-настройки (`setpolicy`, `setthreshold`, `setdownweight`) сохраняются в `config/runtime.py` и применяются без перезапуска. Модераторы работают через inline-клавиатуру в карточках: «Бан/кик», «Не спам», плюс ссылка на сообщение.

## Данные и обучение

- Обучающая выборка: `data/messages.csv` (каталог gitignored, создаётся локально). Публичный источник: [necrasov-ilya/zhiznmart-spam-classification](https://huggingface.co/datasets/necrasov-ilya/zhiznmart-spam-classification) — 5648 сообщений с метками `message`/`label`, анонимизированы токенами, лицензия cc-by-4.0.
- Новые метки, проставленные модерацией, копятся в `data/messages.csv`; при `RETRAIN_THRESHOLD` новых примеров бот рекомендует `/retrain`.
- `scripts/train_tfidf.py` — обучает TF-IDF модель, сохраняет артефакты в `models/`.
- `scripts/train_meta_context.py` — генерирует эмбеддинги контекста и переобучает мета-классификатор (30–60 минут на CPU).
- События модерации пишутся в SQLite-хранилище `storage/`.

## Известные ограничения

- **Скорость.** 800–1200 ms на сообщение, из них ~95% — три вызова эмбеддингов в Ollama. Без GPU одно сообщение обрабатывается до 3 секунд. Для потоков >70 сообщений/мин не годится.
- **Один чат.** Монолитная конфигурация, несколько чатов требуют доработки. Глобальная история пользователя смешивает контекст из разных чатов. В датасете нет `chat_id`, поэтому обучение чат-специфичных моделей невозможно.
- **Эксплуатация.** Нужен запущенный Ollama с `multilingual-e5-small` (~2 GB RAM). Обучение, калибровка порогов и мониторинг метрик требуют ML-опыта.

Для задач, где точность можно отдать за скорость, есть архитектура без эмбеддингов: TF-IDF + LightGBM, латентность <10 ms, precision/recall 0.86–0.90. Подробности и миграция: `docs/MIGRATION_TO_SIMPLIFIED.md`.

## Структура репозитория

```
bot/       обработчики Telegram, клавиатуры, карточки
config/    настройки (.env) и runtime-конфигурация
core/      типы данных, координатор фильтров
filters/   keyword, tfidf, embedding
services/  PolicyEngine, мета-классификатор, менеджер датасета
storage/   SQLite-хранилище событий модерации
utils/     логгер, подготовка текста
tests/     тесты политики и режимов
scripts/   скрипты обучения
docs/      документация
main.py    точка входа
```

`data/`, `models/`, `logs/` создаются при работе и в git не входят (`.gitignore`).
